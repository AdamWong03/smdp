## 0. Update after the published-checkpoint audit

The earlier request was premature. TrajCast is **offline** and reports faithful water
equilibrium; on-policy is not a necessary condition. The decisive variable is the
mode-resolved one-step error relative to the closed-loop amplification.

Before approving on-policy labels, we will:

1. run the **published IBM TrajCast water checkpoint** under our 100 ps NVT screen;
2. quantify the **mode-resolved accuracy threshold** across published / native / 250k models;
3. test the offline **sensitivity-weighted mode error** objective (M1 in the paper plan).

On-policy remains the fallback if M1/M2 fail. The rest of this document records the original
request and its safeguards, which would apply if the fallback is activated.

---

## 1. What is being requested

Use **SPC/Fw one-step reference continuations at states visited by the model** as training
labels for the direct propagator.

This changes the current project rule:

> `diagnose_water_bias.py`: "Diagnostic labels ... are evaluation-only and never train a model."

The change would apply only to the Water method-development line, not to the frozen benchmark
protocols, and only to states generated by the model itself (not to test trajectories).

## 2. Why

The NVT failure is a closed-loop distribution shift, not a one-step accuracy problem:

- One-step gain/variance on held-out NVE pairs is correct to ~1e-4 / ~1e-3.
- On 160 autonomous states, the one-step gain still matches SPC/Fw to ~1e-3, but there is a
  small **signed** internal-KE surplus: +0.0062 eV/step on average, +0.014 eV/step at
  20–100 ps (~0.15–0.3% of internal KE).
- CSVR removes total energy but not the partition; the surplus accumulates into the observed
  factor-of-2.3 internal excess.
- Endpoint, 2-step, 20 ps NVE, 500 fs rollout, and one-step gain/spectral losses cannot see it.

The minimal training signal that targets the drift is the signed mode-resolved KE error on
on-policy states. This is the DAgger / Dynamic Training family (Ross 2011; Žugec 2025).

## 3. Proposed scope (round 1)

| Item | Value |
|---|---|
| Base | 250k Full 6 Å (`dsrt_radius6/best.pt`) |
| On-policy states | 160 pilot labels already generated; expand to ~1,000–2,000 |
| Label | 5 fs SPC/Fw continuation from each visited state |
| Loss | endpoint + λ · signed mode-KE loss + trust-region anchor |
| Replay | reference-trajectory pairs (e.g., 50%) |
| Training | fine-tune 5–20k steps; freeze or unfreeze the backbone as an ablation |
| Evaluation | 100 ps NVT screen (partition, RDF, VDOS, stability); 2.5 ns only if it passes |
| Cost | 2–4 h per round |

## 4. Safeguards

- Test trajectories are never labeled or used; only model-generated NVT states.
- Labels are stored with provenance (`source_checkpoint`, `source_frame`, `seed`) and marked
  `training_use: approved-on-policy-v1`.
- Replay buffer of reference pairs prevents catastrophic forgetting.
- Trust-region anchor (parameter or prediction) to the base model.
- Held-out reference NVE endpoint and 100 ps NVT are reported for every round.
- Negative results are kept, including failed rounds.

## 5. Alternatives if not approved

| Option | Cost | What it tests |
|---|---:|---|
| Mode-resolved thermostat only | 20 min | Whether fixing the partition alone fixes RDF/VDOS/diffusion; no training labels |
| Converged native TrajCast control (float32 resume) | 2–4 days | Whether the published architecture reproduces the paper at convergence |
| Structural/backbone change | ~13 h | Whether capacity/backbone, not training data, is the limit |

The mode-resolved thermostat is the only option that needs no approval and can run immediately.
It is also a useful control for the on-policy round.

## 6. Decision rule

- Approve round 1 → implement signed mode-KE fine-tune, run 100 ps NVT, report.
- Do not approve → run the mode-resolved thermostat control and the converged native control,
  then revisit.
